# 3.6 Accept the Core and Batch Documentation

## Prerequisites

Task 3.5 and explicit acceptance-check/documentation authorization.

## Learning Goal

Evaluate usability, resilience, and reproducibility before extending scope.

## Allowed Scope

Focused existing verification, scoped fixes when authorized, and a milestone batch of project docs/TODO plus the matching root README summary/links/AI-assisted development record.

## Actions

- [ ] Check mobile/desktop screenshots, keyboard navigation, layout fit, and browser errors.
- [ ] Exercise unavailable API/SQL, validation/conflict recovery, and stale BI indicators.
- [ ] Run approved .NET/frontend builds/tests and final real-stack checks; disclose skipped gates.
- [ ] Record verified setup/run/refresh commands and sanitized configuration examples.
- [ ] Summarize classic/modern BI correctness and operational tradeoffs without claiming unverified results.
- [ ] Let the learner update task status and accept the core before selecting stretch work.

## Verification and Acceptance

The learner can reproduce the app and both reports on the intended host and explain boundaries/limitations. No automatic stretch implementation; no commits/pushes without explicit requests.
